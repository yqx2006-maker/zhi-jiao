# 知教（ZhiJiao）· AI＋教育闭环辅导智能体

> GOAI 世界人工智能开源大赛 · 无界应用（Boundless Agents）赛道 · AI＋教育方向参赛作品

知教是一个面向中小学生的 AI 辅导智能体。它不做"拍照搜题、直接给答案"，而是把一次完整的辅导做成一条**可体验、可验证的闭环**：

```
看题 / 听提问 → 追问定位卡点 → 图像 / 实例引导 → 学生自主验证 → 证据式更新学习画像
```

## 目标用户与场景痛点

**目标用户（定位）**
- **学段**：以**初中（七~九年级）**为主攻场景，知识点闭环（一次函数斜率、浮力等）均按初中课标设计；架构与提示词对小学高段 / 高中具备泛化能力，但不宣称全学段覆盖。
- **使用角色**：**B2C 学生直用**为主——学生自己发起提问、完成练习、查看画像；教师端看板为规划项（见后续规划），当前不面向教师常态化使用。
- **典型终端**：桌面 / 移动端浏览器，离线剧本模式亦可运行，降低使用门槛。

**场景痛点（问题定义）**
1. **「给答案」而非「教思考」**：市面拍照搜题类工具直接返回结果，学生跳过推理，长期削弱自主解题能力（对应知教「不直接给答案，先追问卡点」的设计反制）。
2. **卡点无人引导**：学生遇难题常卡在某一小步，却得不到「追问定位 + 图像/实例引导」的渐进帮助，易放弃。
3. **练习无验证闭环**：多数工具止步于「讲完即结束」，缺少让学生**自主验证、证据式更新学情**的环节，学习成效不可见。
> 说明：上述痛点为基于公开教育讨论与一线教学常识的判断，非本项目独立调研的量化结论；本项目不宣称已做大规模用户研究或效果验证。

## 为什么不是"单点问答"

赛道不鼓励通用聊天机器人和单点问答工具。知教的每一次互动都由三个相互依赖的 Agent 环节驱动，缺一不可：

| 环节 | 职责 | 可见产物 |
| --- | --- | --- |
| 诊断 Agent | 阅读对话历史，判断学生卡在哪里 | 界面「为什么这样教」卡片（默认折叠的结构化摘要：观察证据/策略/下一步验证，不展示原始思维链） |
| 教学 Agent | 依据诊断选择策略，苏格拉底式引导 | 流式回复 + 互动练习卡 |
| 画像 Agent | 依据学生行为证据更新学习画像 | 右栏「学习画像」高亮更新 |

诊断结果会作为上下文注入教学环节，教学对话又作为证据注入画像环节——策略摘要、回复、画像三者联动，评审可在界面上逐步核对。

## 闭环任务演示路径（约 90 秒）

1. 打开页面（首屏唯一主入口：**▶ 开始 90 秒完整演示**）。
2. 在滑块上选一个 k（如 k=3）→ 点「用这个例子向我讲解」：消息、图像与讲解全程使用同一个 k。
3. 展开「为什么这样教」卡片：观察证据 / 当前策略 / 下一步验证（剧本模式标注「预设策略」）。
4. 完成选择题 → 回答迁移题（输入「香蕉」等无关答案会被判为证据不足，不会让你蒙混过关；答对才完成闭环）。
5. 闭环完成后：画像四阶段全绿，本轮进度自动写入「学习背景」（跨会话记忆雏形）。

## 能力边界（真实能力 / 预设案例 / 规划项）

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 三 Agent 闭环（诊断/教学/画像） | 真实能力（配置 Key） | 诊断、流式回复、画像均由所选模型实时生成（DeepSeek V4 等） |
| 剧本演示模式 | 预设案例（无 Key 兜底） | 仅提供可点击的预设教学案例；**自由输入不会套用无关剧本**，会如实提示需启动真实模型 |
| 题目图片 | 上传 + 离线 OCR | Windows.Media.Ocr 离线提取题面文字进模型；识别不到则如实请学生口述题意（不做拍照搜题） |
| 多模态提供方 | 可选（自定义提供方勾选） | 视觉模型（如支持图片输入的 OpenAI 兼容 API）可直接接收图片；否则走 OCR |
| 语音提问 | 真实能力（三级降级） | Windows DNN 实时识别 → SAPI 离线转写 → 浏览器 Web Speech；引擎缺失自动降级 |
| 模型提供方管理 | 真实能力 | 页面「配置模型」：预设（DeepSeek/通义/Kimi/GLM/Ollama）+ 自定义，OpenAI 兼容 / Anthropic 兼容双协议，一键切换与连接测试 |
| 话题级会话 + 服务端存档 | 真实能力 | 按“学科::主题”独立存档（v2→v3 自动迁移）；服务端 sessions.json 备份，换浏览器/机器可恢复 |
| 轻量 RAG 知识参考 | 真实能力（内置 kb.json） | 按学科关键词检索知识卡注入上下文，可扩展 |
| 练习卡三层质检 | 真实能力 | 结构校验 + 语义唯一性（多解拦截）+ 年级难度审核；不合格自动重出或放弃 |
| 年级适配 | 真实模式传参 / 剧本预设 | 剧本模式案例标注「预设案例适用年级」，切换年级不改变剧本内容 |
| 跨学科联合提问 | 真实模式动态 / 剧本预设提示 | 剧本模式为逐案例预写的第二学科视角，并明确标注 |
| 学习背景（跨会话记忆） | 雏形 | 闭环验证通过后自动写入进度摘要，随提问发给模型；非长期记忆系统 |
| 教师端看板、RAG 扩展知识库 | 规划项 | 未实现，不在 Demo 中宣称 |

本项目不提供任何未经测试的准确率、通过率或学习效果结论；剧本内容为教学演示预设，不代表实时 AI 判断。

## 数据来源与内容生成

为回应评审对「可复现、可追溯」的要求，明确本项目的全部内容来源与生成方式：

| 内容 | 来源 | 生成方式 | 合规说明 |
| --- | --- | --- | --- |
| 教学法与系统提示词 | 团队自研 | 手写并写入 `server.py`，可审查、可复现 | 原创，无外部抄袭 |
| 剧本演示案例（`SUBJECT_SCRIPTS`） | 团队人工编写 | 基于初中课标知识点手工设计 reason/讲解/练习/迁移闭环 | 教学内容属公共学科知识，非专有数据 |
| 实时诊断 / 讲解 / 练习卡 / 画像 | DeepSeek `deepseek-v4-flash` | LLM 实时生成（流式 SSE），无本地标注数据集 | 调用方自备 Key，见《开源协议与边界说明》 |
| 验证练习（quiz） | LLM 即时生成 | **非来自精选题库**，每次按当前对话动态产出；严格校验「≥2 选项且恰 1 正确」才下发 | 属生成式内容，不保证覆盖率与难度标定 |
| 学习画像 | LLM 即时生成 | 依据对话证据输出结构化 JSON，证据不足时显式标注「待验证」 | 不编造未表现出的行为 |
| 语音识别文本 | 系统引擎 / 浏览器 | Windows SAPI/DNN 离线转写或 Web Speech | 不上传第三方模型训练 |
| 跨会话记忆 | 前端 localStorage | 仅存浏览器本地，不上传 | 见隐私说明 |

**明确边界**：
- 本项目**当前无任何自建训练集 / 标注题库 / RAG 知识库**；全部教学智能来自「公共课标知识 + LLM 推理 + 人工编排的剧本」。
- 练习卡为生成式输出，**不宣称经过教育测量学验证**；其作用是闭环「自主验证」环节的演示载体，不代表标准化测评。
- 剧本案例用于无网络 / 无 Key 环境的可复现演示，已在前端与徽章中明确标注「预设演示案例」，不与实时 AI 判断混淆。

## 快速开始

要求：Python 3.8+（仅用标准库，**零第三方依赖、无需 pip install**）。

```bash
# 1. 配置模型（可选：不配置则自动进入剧本演示模式）
cp .env.example .env      # Windows: 复制 .env.example 为 .env
#    编辑 .env，填入你的 DeepSeek API Key

# 2. 启动（或直接双击 start.bat）
python server.py

# 3. 打开浏览器访问
http://localhost:8000
```

两种运行模式（顶栏徽章实时标明）：

- **真实模型模式**（配置了 `DEEPSEEK_API_KEY`）：调用 DeepSeek 开源模型，流式输出，策略摘要、练习卡与画像由模型实时生成；自由提问可用。
- **剧本演示模式**（未配置 Key 或后端不可用）：仅提供预设教学案例（均标注「预设演示案例」），自由输入会如实提示需启动真实模型——**绝不把预设规则包装成实时 AI 回答**；后端失败也如实报错，不偷偷回退伪装。

## 技术架构

```
浏览器（web/index.html，零依赖单文件，唯一入口）
  │  FormData: text / grade / subject / profile / files（图片）
  ▼
server.py（Python 标准库，ThreadingHTTPServer）
  ├─ GET  /api/health     健康检查（含当前提供方/模型，前端据此选择模式）
  ├─ GET  /api/providers  提供方列表 / 预设（页面「配置模型」）
  ├─ POST /api/providers  添加/切换/删除/测试 提供方（OpenAI 兼容 / Anthropic 兼容）
  ├─ POST /api/config     兼容旧「配置 Key」入口（写入 DeepSeek 提供方）
  ├─ POST /api/chat       SSE 流式对话管线
  │     ① 诊断调用  → event: reason   （「为什么这样教」结构化摘要）
  │     ② 流式回复  → data: 增量文本   （教学 Agent）
  │     ③ 验证练习  → event: quiz      （自主验证选择题，三层质检：结构/唯一性/年级难度）
  │     ④ 画像调用  → event: profile  （学习画像 JSON）
  ├─ POST /api/quiz       练习卡作答回传（证据入上下文 + 画像推进 + 下一步练习卡）
  ├─ GET/POST /api/sessions  服务端会话存档（跨浏览器/机器恢复）
  ├─ POST /api/asr        离线语音转写（Windows SAPI，零联网零密钥）
  ├─ POST /api/asr_live   实时语音转写（Windows 10/11 新一代 DNN 引擎）
  ├─ POST /api/reset      清空会话上下文
  │   （附：tools/ocr.exe 离线 OCR 提取题面文字；kb.json 轻量 RAG 知识参考；敏感词拦截）
  ▼
模型提供方 API（默认 DeepSeek V4，stream=true；可切换通义/Kimi/GLM/Ollama/自定义）
```

前端同样是零依赖单文件：SSE 流式解析、语音提问（优先后端 Windows 10/11 新一代 DNN 引擎实时聆听；自动降级为前端录音 + SAPI 离线转写，并由 LLM 纠正文本中的同音错误；非 Windows 环境再降级为 Web Speech API）、**题目图片上传（离线 OCR 提取题面文字进模型；识别不到则如实请学生口述题意；多模态提供方可直接接收图片）**、localStorage 学习记录持久化 + 服务端会话备份、响应式三栏布局与无障碍支持。

## 为什么选择零依赖实现

评审可复现性是 GOAI 的评审重点。本项目刻意只用 Python 标准库与浏览器原生 API：克隆仓库后 `python server.py` 一步启动，没有 pip、没有 node、没有构建步骤，任何机器 30 秒内可复现 Demo。

## 教学法设计（写入系统提示词）

1. 不直接给答案，先追问定位卡点；
2. 每次只问一个小而具体的问题；
3. 优先用生活类比与图像对比解释抽象概念；
4. 学生答错不否定，先肯定正确部分再引导；
5. 证据不足时使用低置信度表述（"初步观察/待验证"），不编造学生行为。
